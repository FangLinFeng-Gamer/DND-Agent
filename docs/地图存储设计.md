# 地图存储设计

## 背景

地图系统需要同时支持地图底图、token、道具图、场景画布配置、网格、图层、墙体、光源和迷雾。参考 Roll20、Foundry VTT、Owlbear Rodeo 和 PlanarAlly 的产品模型，本项目不把地图图片直接写入数据库，而是拆成“媒体文件”和“场景元数据”两部分。

## 本期目标

本期实现本地优先的地图存储底座：

- 地图、token、道具图片保存为本地文件。
- SQLite 保存资产元数据和场景配置。
- 冒险会话可以绑定一个当前地图场景。
- 前端提供最小可验证入口：上传地图、创建场景、绑定到当前冒险、查看预览。

## 存储模型

### map_assets

保存图片资源元数据。

- `id`: 主键
- `name`: 显示名称
- `asset_type`: `map`、`token`、`prop`、`portrait`
- `storage_key`: 本地文件相对路径
- `mime_type`: MIME 类型
- `sha256`: 文件哈希，用于去重和稳定寻址
- `size_bytes`: 文件大小
- `width`: 图片宽度，可为空
- `height`: 图片高度，可为空
- `metadata_json`: 扩展信息
- `created_at` / `updated_at`

### map_scenes

保存可复用场景。

- `id`: 主键
- `name`: 场景名称
- `adventure_id`: 可为空，绑定冒险时使用
- `story_id`: 可为空，未来可绑定剧本模板
- `grid_type`: `square`、`hex`、`none`
- `grid_size`: 网格像素大小
- `scale`: 每格代表的距离，默认 5
- `scale_unit`: 默认 `ft`
- `background_color`: 画布背景色
- `active`: 是否为冒险当前地图
- `created_at` / `updated_at`

### map_scene_items

保存资源在场景中的摆放信息。

- `id`
- `scene_id`
- `asset_id`
- `item_type`: `background`、`token`、`prop`
- `layer`: `background`、`object`、`token`、`gm`
- `name`
- `x` / `y`
- `width` / `height`
- `rotation`
- `locked`
- `visible`
- `metadata_json`

### map_walls / map_lights / map_fog_shapes

本期先落库和 API 数据结构，前端高级编辑放到后续版本。

- `map_walls`: 墙、门、窗、地形线段
- `map_lights`: 光源坐标、半径、颜色、强度
- `map_fog_shapes`: 迷雾或已探索区域的几何 JSON

## 文件存储

默认资产目录为：

`data/assets`

文件路径使用 SHA-256 分片：

`data/assets/{sha256前2位}/{sha256}.{扩展名}`

数据库只保存相对 `storage_key`，API 通过 `GET /api/map-assets/{id}/file` 读取文件，避免前端直接访问任意本地路径。

## API

### 资源

- `POST /api/map-assets`
- `GET /api/map-assets`
- `GET /api/map-assets/{asset_id}`
- `GET /api/map-assets/{asset_id}/file`
- `DELETE /api/map-assets/{asset_id}`

#### 上传格式

当前项目依赖中没有 `python-multipart`，因此本期不使用 multipart 表单上传。前端读取文件为 `ArrayBuffer`，用原始图片字节请求：

`POST /api/map-assets?asset_type=map&name=Ruins&filename=ruins.png`

请求头：

`Content-Type: image/png`

后端根据 `Content-Type` 校验图片类型，根据文件内容计算 SHA-256 并写入本地资产目录。

### 场景

- `POST /api/map-scenes`
- `GET /api/map-scenes`
- `GET /api/map-scenes/{scene_id}`
- `PATCH /api/map-scenes/{scene_id}`
- `POST /api/map-scenes/{scene_id}/items`
- `PATCH /api/map-scenes/{scene_id}/items/{item_id}`
- `POST /api/map-scenes/{scene_id}/activate`

## 冒险和战斗关系

`map_scenes.adventure_id` 表示场景归属于某次冒险。`active = 1` 表示该冒险当前使用的地图。后续 DM agent 和 NPC 行动逻辑可以读取当前 active scene，将 token 坐标、墙体、光源和周围敌人作为战斗上下文。

## 非本期范围
